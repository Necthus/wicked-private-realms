# 本地国度与主动共享（v0.2.4）

通过启动器登录私服后，游戏仍可创建和游玩本地国度。创建或进入纯本地国度时，不上传该国度；选择游戏中的“共享”后，才通过原有 Realm.Upload 流程创建服务器记录。

角色和国度分别保存：本地国度不上传，不代表已有云端角色也停止同步。启动器本身仍需连接服务器完成登录。

## 修正原因

v29466 的 `ClientFlowAPI.ProceedToSession` 在登录后会先调用 `EnsureRemoteSaves`，自动上传缺少远端记录的角色与国度。私服将所有上传的国度作为共享国度，所以这一自动上传使新建的本地国度意外变成在线国度。

当前适配器对明确的纯本地条目（missingIndex=-1、localIndex>=0、remoteIndex=-1），跳过入场时的 EnsureRemoteSaves；原游戏继续创建本地会话和本地存档。远端条目、合并条目及未知状态仍交给原函数处理。

“共享”按钮独立调用 Realm.Upload，该方法保持原样，不受这次入场拦截影响。已共享的单成员国度继续使用在线流程。

序章参数同样交由原游戏决定，详见 [序章恢复](PROLOGUE-RESTORE.md)。DLL 自检覆盖纯本地、纯远端、合并和缺失条目，完整成功掩码为 0x7F。

## 保存与恢复

本地世界使用游戏原有 Steam ID 存档目录。此前误上传的世界可使用游戏自身的读取、转换与创建函数恢复本地副本；应先完整备份本地存档与服务器数据库，确认本地副本可读取并保存后，再归档原服务器记录。归档记录及历史版本保留，不应直接丢弃最新世界内容。
